# Game-owned screenshot pilot

The Hours We Keep (`kata-inspired-by-braid-codex-dot`) and Parallax Relay (`kata-inspired-by-portal-codex-dot`) own `public/arcade/manifest.json` and `public/arcade/screenshots/*.jpg`. Vite includes `public/` unchanged in each game's build. Their v1 manifests specify the repository ID, exact play URL, image paths, SHA-256 hashes, alt text, and per-image provenance. Their current images are **existing repository captures** with unknown capture dates and deployed-build identities. They are not automated captures of the current deployment. Moving or syncing them does not change that status.

The arcade remains the discovery hub. `node scripts/pilot-sync.mjs [game-checkout-parent]` validates the two local game-owned manifests and image hashes, then generates `src/data/pilot-screenshots.json` and content-addressed copies under `public/screenshots/game-owned/`. The snapshots are committed with the arcade, so ordinary builds need no network or adjacent checkouts. A sync validates both inputs before writing and atomically replaces the index last; a failed validation leaves the previous index in place. The game detail page and gallery previews prefer the pilot snapshot; all other games retain their current images and missing-image fallback. A full sync is an explicit reviewable maintenance action, not a runtime fetch. Previous content-addressed copies can be removed only after confirming they are no longer referenced by a deployed or proposed index.

The initial release snapshot was synced from the two deployed game manifests after verifying each of their five image hashes. That confirms the source assets matched those manifests at sync time; it does not establish when the images were captured or which game build they depict.

## Capture convention for future work

A game-specific, pinned Playwright version and browser could run in CI against the exact built artifact served at `http://127.0.0.1`, using a fixed viewport, locale, clock, seed, and a clean storage state. A game-specific public interaction script should wait for a verifiable ready state, enter representative gameplay without hidden debug shortcuts, and call Playwright's documented `page.screenshot({ path: ... })` API ([Playwright screenshots](https://playwright.dev/docs/screenshots)). Human review should check that each image depicts the intended game and state, includes no private data or browser chrome, and remains readable. This is a proposed convention, not an implemented or verified capture pipeline; no new browser screenshot has been captured by the pilot.

A future automated manifest schema must separately record capture timestamp, source commit, build artifact digest, capture tool/browser versions, and whether it depicts a local artifact or a verified deployment. To claim an exact deployed build, verify the deployed artifact against that digest or an equivalent trusted deployment attestation; a commit SHA or successful capture alone is insufficient. Never silently relabel older images. A failed capture, missing manifest, invalid hash, deployment mismatch, or unavailable network must retain the last validated snapshot with its existing provenance or show a no-screenshot state; it must not prevent play links or substitute another game's images. The current v1 sync deliberately accepts only `existing_repository_capture` with null date and deployed build, so it cannot accidentally assert a fresh deployment.

## Gradual rollout

1. Review these two game manifests, their assets, and generated gallery changes. Deploy game-owned manifests and assets before any future gallery release that links to their published URLs; this pilot uses local checked-in snapshots and does not depend on those URLs.
2. Establish and test a capture workflow per game in a suitable authorized automation environment; audit output and provenance before replacing any existing captures.
3. Expand in small batches with schema, identity, hash, attribution, mobile, and gameplay checks. Keep unknown or unavailable images honest and leave legacy fallback in place.
4. Consider fetching versioned published manifests only after integrity, caching, failure handling, supply-chain trust, and review policies are designed. Do not make normal gallery builds depend on a live endpoint.
